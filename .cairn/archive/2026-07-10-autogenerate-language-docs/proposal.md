## Why

Kamacite already has a validated documentation IR and projection receipt boundary, but documentation facts are still hand-authored fixtures. To autogenerate documentation for the Rust, Nickel, and Steel parts of the stack, Kamacite needs a first-class source-collection layer that turns preserved source envelopes into bounded documentation facts before those facts are assembled into documentation IR.

Without that layer, generated docs would either bypass Kamacite identity/non-claim rules or duplicate language-specific collector logic in downstream repositories. Kamacite should own the interchange boundary: language collectors produce canonical, receipt-backed doc facts; documentation IR consumes those facts; renderers remain derived projections.

## What Changes

- Add a Kamacite language documentation facts artifact for Rust, Nickel, and Steel collector outputs.
- Add source collectors that preserve source-envelope identity, collector identity, spans, item paths, signatures or contract summaries, doc blocks, examples, links, runnable-cell references, dependencies, diagnostics, and non-claims.
- Add a pure planner that assembles language documentation facts into existing documentation IR pages, sections, anchors, runnable cells, and render plans.
- Add explicit CLI commands for collecting, checking, rendering, running cells, and updating generated documentation.
- Add WASM as an explicit runnable documentation cell execution target that binds module identity, engine identity, declared imports, capabilities, resource limits, outputs, diagnostics, and non-claims without making WASM the Kamacite IR.
- Require Nickel-authored docs configuration with typed contracts for source roots, languages, output formats, collector identities, run profiles, WASM runner profiles, link policies, and update behavior.
- Add positive and negative fixtures for Rust, Nickel, Steel, WASM-backed examples, cross-language links, generated documentation IR, renderer outputs, receipt binding, stale hashes, duplicate anchors, unknown links, collector drift, unsupported languages, missing evaluator identity, undeclared capabilities, runner drift, resource-limit violations, and non-claim violations.

## Impact

Kamacite can become the source of truth for autogenerated stack documentation without claiming arbitrary source-language semantic equivalence. Downstream repos can consume documentation IR, rendered projections, WASM-backed example receipts, and documentation receipts while preserving the boundaries that rendered output is not canonical authority, WASM is an execution adapter target rather than canonical IR, and runnable examples are checked only under explicit profiles.
